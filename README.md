# LoL Overlay

観戦配信用のローカルオーバーレイ。要件に沿った初期実装です。PythonとHTML / CSS / JavaScriptで動作します。OCRはPillow・PyWinRTとWindowsのローカルOCRを使用します。ゲーム情報の取得にRiot・LCU・Live Client・外部サービスのAPIは使用しません。

**配信用の画像素材を制作する方へ**。デモでは、チーム名や成績を重ねた状態で背景や装飾枠を確認できます。[画像のサイズ・ファイル名・差し替え手順](assets/overlay-art/README.md)

## 起動

OBS配信の設定とブラウザ診断: <http://127.0.0.1:8765/obs>。OBSにはゲームキャプチャを下層、透過ブラウザソース `/overlay` を上層として追加し、幅1920・高さ1080を指定します。[OBS公式のブラウザソース説明](https://obsproject.com/kb/browser-source)。操作画面や `/watch` を本番のブラウザソースには指定しません。

`/obs` では本番と同じ出力、サーバー更新番号、シーン・ふた絵状態を確認できます。これはOBS内部の接続検出ではありません。「OCRエンジンを検査」は合成文字3項目を実際のローカルOCRで読み、期待値と比較します。試合データは変更しません。PASSは実ゲームの認識精度を保証しません。

実ゲームの検証は <http://127.0.0.1:8765/?tab=vision> を使用します。元画面を選択して枠を調整しOCRを実行すると、取得時刻・入力解像度・処理時間・不一致/読取不能件数、各候補の読取時の切出し画像をブラウザに表示します。動画が進んでも切出しはそのOCR実行時の画像のままです。画像と候補を比較して採用し、「本番へ反映」でOBSへ送ります。切出し画像はブラウザ内の一時表示のみで、試合保存JSONに含めません。

1. Windows 10 / 11、Python 3.10以上を用意します（開発確認環境: Windows / Python 3.12）。初回は `setup.bat` を実行して `.venv` に依存ライブラリを入れます。セットアップ時のみパッケージのダウンロードにネット接続が必要です。
2. `start.bat` をダブルクリックするか、このフォルダで `.venv\Scripts\python.exe server.py` を実行します。
3. 操作画面: <http://127.0.0.1:8765/>
4. OBSにブラウザソースを追加し、URLを `http://127.0.0.1:8765/overlay`、幅1920・高さ1080に設定します。観戦映像より上のレイヤーに置いてください。
5. 操作画面のプレビューを確認して「本番へ反映」を押します。

サーバーのコンソールを閉じると同期が停止します。終了はCtrl+C。ポートが使用中なら `python server.py --port 8766` とし、操作・OBSの両方に同じポートを指定します。URLのホスト名は `127.0.0.1` を使用してください。別PCからは接続できません。

## 試験デモ

`demo.bat` をダブルクリックすると、ローカルサーバーを起動して自動上映を開きます。起動済みのサーバーは再利用します。BAN/PICK → 試合中（バロン獲得演出）→ 試合結果 → 中断を12秒ずつ繰り返します。進行バーと次の切替までの残り秒数を表示します。SPACEで自動上映の開始・停止、1〜4でシーン選択、Fで全画面、ESCで全画面を終了できます。ボタンにフォーカスがあるときは通常のキーボード操作を優先します。

サーバーは画面を閉じた後も動作します。デモ起動時のログは `data/demo-server.log` です。停止する場合はタスクマネージャーで、このフォルダの `server.py` を実行しているPythonプロセスを終了してください。

- デモ上映: <http://127.0.0.1:8765/demo>。架空のAZURE FOX / CRIMSON OWL、10選手のチャンピオン・BAN・KDA・ダメージを収録しています。シーン切替、獲得演出、12秒ごとの自動再生、全画面表示ができます。
- 試験編集: <http://127.0.0.1:8765/?demo=1>。「試験表示へ反映」で `data/demo.json` に保存します。初期サンプルは `fixtures/demo.json` にあり、編集画面から下書きに戻せます。本番の `data/live.json` とは独立しています。
- OBS試験出力: `http://127.0.0.1:8765/overlay?demo=1`（1920×1080）。試験編集で保存したシーンを表示します。デモ上映ページ内のシーン切替・自動再生は、そのページだけに適用されます。

試験画面には架空データの表示が入ります。数値は作成したサンプルで、OCRの読取結果ではありません。上映ページの背景も説明用の図形で、実ゲーム映像ではありません。

## 操作

プレビュー下の「BAN / PICK・試合中・試合結果・中断」を選ぶと、下書きのシーンと対応する入力欄が切り替わります。画面上部で現在の本番シーンを確認し、「本番へ反映」でOBS出力を更新します。スクロール中も反映ボタンを使えます。OCR・配置調整、JSON保存、次の試合の準備は「詳細設定」から開きます。

- **チーム**: チーム名・各5名の選手・ローカルロゴの編集、Blue / Red交換。ロゴはPNG / JPEG / WebP、2MB以下。
- **試合中**: キル数・チーム合計ゴールド、取得記録、獲得演出。
- **中断**: ふた絵の見出しと補足。
- **BAN / PICK**: 顔画像を見ながら各5選手のPICK・5枠のBANを手動選択。日本語・英語検索と重複選択防止に対応。進行中のチーム・BAN/PICK・枠を配信表示で強調します。大会参考配置では中央カメラ領域を透過で残します。
- **終了後**: 勝利チーム、各選手のKDA・総ダメージ、集計対象のラベル。ゴールド差は両チームの最終入力値から算出します。
- **保存・設定**: JSONバックアップと読込、本番からの再読込、次の試合のリセット。

編集はすべて下書きです。プレビューの再生や取得追加は本番に影響しません。「本番へ反映」は下書き全体を反映します。演出は6秒間で、明示的に新規再生したものを反映した場合に本番で開始します。再生済みの演出は他の編集の反映では再実行しません。終了操作も本番反映が必要です。

「取得を記録」は下書きへ1件追加する操作で、「演出をプレビュー」は取得数を変更しません。実際の取得1回につき記録を1件追加してください。誤って複数追加した場合は取消できます。同じ下書きの再反映では二重加算されません。ヴォイドグラブは暫定的に入力1件を1取得として数え、個体数・グループ数は運用確定が必要です。

空欄の数値は未確認を意味し、「—」で表示します。0は入力した場合だけ表示します。ゴールドが片方でも未入力なら差は表示しません。オブジェクト数は確認済み取得記録の件数です。画面認識による補完・推測は行いません。

## 保存と同期

### チャンピオン画像と手動ドラフト

Riot公式Data Dragon **16.18.1の全173体**の顔画像（128×128 PNG）と日本語名・英語名・IDを `assets/champions/` に保存しています。ラベル・取得URL・SHA-256は `catalog.json`、元の言語別一覧は `ja_JP.json` / `en_US.json` です。スキン一覧・スプラッシュ画像は対象外です。画像の取得時のみ公式CDNへ接続し、操作・配信中はローカル素材を使用します。更新は `.venv\Scripts\python.exe tools/download_champions.py` で実行できます。

1. 「BAN / PICK」→「空のドラフトを開始」。下書きの選択を空にし、BLUE BANから開始します。
2. 「現在の枠を選択」で画像から選択し、「確定して次へ」で次の手順へ進みます。
3. プレビューを確認して上部の反映ボタンを押すと、OBSにも現在の進行と選択が反映されます。
4. 「一手戻る」や「手順へ移動」で手動修正・再現できます。移動しても既存の選択は消えません。各枠の×で解除できます。

プリセットは、BANがB/R/B/R/B/R → PICKがB/R/R/B/B/R → BANがR/B/R/B → PICKがR/B/B/Rの20手です。大会ごとの独自ルール・Fearlessの過去試合制限・タイマーは実装していません。手順を任意に移動できるため、全枠の埋まり具合と進行表示は操作者が確認してください。PICK枠は選手1〜5に対応します。進行表示をOFFにしても選択画像は表示されます。

本番反映時に `data/live.json` を一時ファイルから置換して保存します。名前・画像のData URL・サイド・試合情報・ふた絵を含みます。サーバー再起動で復元し、一時演出は復元しません。保存データが壊れている場合はエラーで起動を止め、黙って初期化・上書きしません。

下書きはブラウザのメモリ上にあり、再読込で失われます。残すにはJSON保存を使ってください。読込はプレビューのみを更新します。試合結果の履歴は自動保存しないため、必要な試合ごとにJSONを書き出してください。複数操作画面からの古い編集の反映は競合エラーで拒否します。必要なら下書きを書き出してから「本番から読み直す」を使います。

同一PC内のHTTPを画面間のローカル通信として使用します。`/state` は自前の保存状態、`/publish` は操作画面の手動入力を扱う内部経路で、LoLから情報を取得するAPIではありません。Riot / LCU / Live Client / 外部サービスへの通信・メモリ読取・パケット解析はありません。サーバーはループバックにのみバインドし、Host / Originを検証します。本番画面は300ms間隔で状態を読み、通信停止中は最後の表示を維持します（期限付き演出は終了します）。

## 参考画面・OCR

「詳細設定」→「OCR・配置調整」から操作します。保存した4枚の大会画像は、目指す配信画面のデザイン参考です。OCRは合成前のゲーム画面に対して使用します。原画像と掲載元は `references/` 内にあります。[出典と検証範囲](references/SOURCES.md)を参照してください。

1. 完成参考の大会画像とシーンを確認します。この画像はOCR取得元には設定されません。
2. ゲーム画面用の読取設定を選びます。`config/ocr-profiles.json` の初期枠は未校正のひな形であり、実ゲーム画面で位置合わせが必要です。
3. 実運用では「元映像のウィンドウを選択」で合成前のゲーム・リプレイ・動画ウィンドウを選び、元映像確認チェックを入れます。Chrome / Edgeを推奨。画面選択ダイアログはユーザーが操作します。ローカルPNG / JPEG / WebP / MP4 / WebMも入力可能です。
4. 元映像は余白・ウィンドウ枠を除いた16:9にします。読取枠を選び、ドラッグか座標入力で文字に合わせて調整します。枠の座標は1920×1080基準です。「取得元をプレビュー背景に表示」で重なりを確認できます。背景は本番には出ません。画像入力時も、取得元がゲーム画面であることを確認してください。
5. 「OCRを1回実行」または「連続読取を開始」。連続読取は前回処理完了から3秒後に再実行し、処理を重複させません。
6. 認識文字と元画像を比較し、採用する項目だけチェックして「選択した候補を下書きへ」。プレビューで確認してから「本番へ反映」します。

採用前の結果が本番・取得記録を変更することはありません。OCR後に試合リセットやサイド交換をした場合、その候補の取込は拒否します。元画像・読取枠を変更した場合も古い候補を破棄します。識別不能・前処理間で不一致の項目は採用できず、既存値を維持します。

2種類の前処理を比較しますが、Windows OCRは数値の信頼度を返さないため、信頼度のパーセントは生成していません。「2方式一致」「連続一致」は参考情報で、誤読がないという意味ではありません。全候補の採用チェックは毎回オフです。

キル・ゴールド・個人KDA・ダメージ・明示的なWIN表記のOCRに対応。`k/K` は千の単位に変換します。10選手のKDAは試合中のスコアボードから、ダメージは終了後の表示から取得します。**大会の終了後画面にあるチーム合計KDAを個人KDAには流用しません。** 勝者の推測・チャンピオンやBAN肖像の画像認識・オブジェクトの自動取得記録は行いません。

英語OCR言語がWindowsに必要です。この環境では利用可能であることを確認済みです。認識エンジンはローカルで動き、フレームはクラウドに送信しません。フレーム本体は保存せず、一時的な切出し画像だけをOSの一時フォルダへ書き、処理終了時に削除します。読取枠は本番反映時のJSONに保存します。キャプチャ許可と元映像選択は再起動後に引き継ぎません。

## 現時点の範囲と調整箇所

- 同一Windows PC、1920×1080基準。手動入力とローカルOCRの併用に対応します。画面の自動シーン判定・自動本番反映は行いません。
- 保存した大会画像を基準に配置を設定済み。試合中は上部のみ、BAN/PICKは左右・上部・下部のみを覆い、中央カメラ領域を残します。試合結果・ふた絵は全面不透明です。配置はOCRタブで調整・保存可能です。
- OBSと現行LoLの実機合成・ライブキャプチャの動作は未検証です。実際のゲームUIスケールに合わせた読取枠調整が必要です。
- 選手名はBAN / PICKと終了後に表示。BAN / PICKはローカルの顔画像・日本語名と20手順の手動進行に対応します。タイマーはありません。
- 終了後のダメージは元のゲーム画面で集計対象を確認し、表示ラベルを合わせてください。実運用の取得画面・UIスケール・許容遅延・認識精度は別途確認が必要です。ゴールド差は最終値のみで、時系列グラフはありません。
- レイアウト・アニメーションは仮デザインです。アプリ単体の表示確認と、OBS・実ゲームでの受入確認は別です。

## 構成・検証

`server.py`: ローカルホスト・検証・永続化 / `web/app.js`: 操作と独立下書き / `web/overlay.js`: 共通描画 / `web/style.css`: 操作・配信レイアウト。

```powershell
.venv\Scripts\python.exe -m unittest discover -s tests -v
.venv\Scripts\python.exe tools/check_reference_ocr.py
node --check web/app.js
node --check web/overlay.js
node --check web/vision.js
node --check web/demo.js
node tests/test_draft.cjs
```

手動受入: プレビューで名前・ロゴ・ふた絵を変更して本番が変わらないこと → 本番反映 → サイド交換後も記録が同じチームに属すること → 同じ取得を反映し直しても件数が増えないこと → 再起動で復元 → 結果表示・次試合リセットを確認します。

OCRの固定画像試験は、開発時に大会画像で確認した28項目のエンジン回帰試験です。ゲーム元画面用の枠の校正・精度検証ではありません。全画像・全項目の成功を意味しません。試験ログは `data/ocr-reference-report.json` に出力されます。実ゲーム画面の読取精度とライブキャプチャは未検証です。

## 観戦映像との合成確認

http://127.0.0.1:8765/watch をChrome / Edgeで開き、観戦ウィンドウを選択すると、ゲーム映像と試合中オーバーレイをブラウザ内で重ねて表示します。画面選択と許可は利用者が行います。ゲームに直接描画するものではなく、録画・配信は開始しません。架空デモ数値への切替と全画面表示に対応します。表示数値は反映済みの手動入力/OCR値であり、画面を選ぶだけでは認識しません。
